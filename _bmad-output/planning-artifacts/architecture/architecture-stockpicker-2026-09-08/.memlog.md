- (decision) Rendering: server-rendered PHP. Front controller (public_html/index.php) grows human-facing routes (/login, /, /watchlist, /list, /stock/{isin}) alongside the existing cron routes, same file, same switch-based routing style. No JSON API, no client-side framework, no build step. Binds: public_html/. Prevents: a second deploy pipeline (Node/bundler) on Loopia shared hosting where none exists today.
- (decision) Auth: stateless signed cookie, not PHP native sessions. On login, issue a cookie carrying an expiry (now + 30 days) and an HMAC signature keyed by a new config.php secret (same pattern as cron_token). Every authenticated route re-validates signature+expiry via hash_equals; no server-side session storage, nothing to garbage-collect. Binds: config.php, all human-facing routes. Prevents: session lifetime silently governed by Loopia's uncontrolled php.ini session GC settings.
- (decision) New layer: src/Web/ for UI request handling (leaderboard ranking/filtering, full-list search, stock-detail assembly), sibling to src/Pipeline/, both calling only into src/Store/. - (decision) Watchlist ownership: new 'watchlist' table (isin PK/FK to instrument, starred_at), new WatchlistRepository in src/Store/, written only by src/Web/. First write path in the system that isn't the nightly pipeline. Binds: watchlist table, WatchlistRepository, src/Web/. Prevents: a second writer to any pipeline-owned table, and ambiguity about who may write watchlist rows.
- (decision) Credentials: username + bcrypt password hash stored in config.php (same location/spirit as cron_token), verified via password_verify(). No registration, no password-reset flow, no users table.
