# Rubric Walker Review — Stockpicker Architecture Spine

## Overall verdict
The 2026-09-12 update is structurally sound and internally coherent for the new web-UI capabilities (AD-12–AD-15, K13–K18 all trace to real UX requirements and real Rules), but it ships with one un-reconciled stale diagram, one silently-broken guarantee (AD-2 was touched despite the update's own "only AD-10 changes" framing), one missing cross-cutting decision (UI language) that the memlog itself flagged as unresolved, and a real brownfield collision on the `/` route that no implementer would know to look for.

## Findings

- **high** The "Körflöde per natt" (nightly-run) sequence diagram still shows `/cron/derive` calling `Deriver`, which then `materialiserar/uppdaterar härledda mått` — but Story 3.1/3.2 already settled `owner_count_metrics` as a plain SQL view, and the shipped `/cron/derive` handler (`public_html/index.php:156-198`) never calls `Deriver` or `DerivedMetricsRepository` at all; it only counts instruments and writes an `ingest_run` row. The spine's own K10/Deferred sections already reflect the view-based design (the "view vs materialized table" Deferred bullet was correctly removed this update), so this diagram is now the one place still contradicting the spine's own settled reality. (ARCHITECTURE-SPINE.md, "Körflöde per natt" mermaid sequence, ~line 340-357; contradicted by `public_html/index.php` lines 156-198 and `src/Pipeline/Deriver.php`'s own doc comment). *Fix:* redraw the nightly sequence diagram's `/cron/derive` leg to show it logging an `ingest_run` row directly, with no `Deriver` call, matching the human-facing/watchlist diagrams' accuracy bar.

- **high** The Structural Seed and Consistency Conventions claim `/` will be the topplista (Leaderboard) route once K14 is built, but `public_html/index.php`'s current `case '/':` handler already returns a JSON health-check payload (`{"status":"ok","app":"stockpicker",...}`). Nothing in the spine (Deferred, AD-12, AD-14, or the routes convention row) acknowledges that this pre-existing `/` handler exists and must be relocated or removed before `/` can become the human Leaderboard page — a genuine, silent divergence point for whoever implements K14 first. (ARCHITECTURE-SPINE.md "Människovända routes" convention row and Structural Seed, vs. `public_html/index.php` lines 51-58). *Fix:* add a one-line note (Deferred or AD-12) deciding where the existing JSON status check moves (e.g. `/health` or under `/cron/*`) before `/` is repointed to the Leaderboard.

- **medium** The memlog (`.memlog.md` line 25) logs an explicit, unresolved constraint surfaced during this session: "Product UI language: the webpage itself (all visible microcopy, labels, dates) must be in Swedish... a real gap to reconcile with the UX spine," followed by a decision (line 26) that "the product UI itself" is Swedish. This decision never lands anywhere in the spine — no AD, no Consistency Convention, not even a Deferred bullet — despite being exactly the kind of cross-cutting constraint (affects every controller in `src/Web/` that renders user-facing text, including error/empty-state copy) that a spine update claiming to "extend the v1 spine to cover the web UI/read layer" should fix. *Fix:* add a Consistency Convention row ("UI-text: all human-facing microcopy/labels/dates in `src/Web/` output are Swedish") or a Deferred bullet pointing at the planned bmad-ux Swedish-translation pass, so the constraint is at least visible to an implementer reading only the spine.

- **medium** AD-2 was modified in this update (added `AdapterError` base class and the `RateLimited` subtype to its Rule text, plus the matching Structural Seed and Consistency Conventions edits) even though the spine's own framing promises "AD-1 through AD-9 and AD-11 genuinely untouched" and only calls out "new ADs (AD-12 through AD-15, plus the AD-10 amendment)." The memlog does log this as a deliberate "staleness fix... unrelated to this update's decisions" (entry 37) and the change is factually correct (matches `src/Error/AdapterError.php` and `RateLimited.php`), but it's an undisclosed exception to the update's own untouched-ADs guarantee. *Fix:* either restate the update's scope line to say "AD-1, AD-3–AD-9, AD-11 untouched; AD-2 corrected for staleness" or move the AD-2 fix into its own explicitly-labeled changelog note so a reader isn't misled by the blanket "untouched" claim.

- **medium** The Deployment section is unchanged by this update (confirmed via diff), but AD-13 adds two new required secrets to `config.php` (session-signing secret, plus username + bcrypt password hash) on top of the existing DB credentials and cron token. The Deployment section's `config.php` bullet ("kopieras manuellt en gång, aldrig via rsync, aldrig i git") is the natural place an implementer checks before first deploy, and it says nothing about needing to populate these two new keys — someone following only the Deployment section could ship the K13-K18 feature set with a missing session secret or login credential. *Fix:* add a clause to the Deployment section's `config.php` bullet noting the AD-13 keys must be present before this feature's first deploy.

- **low** The Structural Seed lists `src/Web/`'s five controllers but never fixes where their HTML output/view templates live (no `templates/`, `views/`, or `.phtml` convention anywhere in the spine, despite AD-12's whole point being "everything renders server-side in PHP"). Two implementers could reasonably diverge — inline `echo`/heredoc in the controller vs. separate template files included by the controller — without either violating any stated Rule. *Fix:* add one line to Structural Seed or AD-12 fixing (or explicitly deferring) where view markup lives.

- **low** K15's "Styrs av" column cites AD-3 and AD-10 for "never merge sources," but the Rule that actually enforces per-source query scoping in the web layer is AD-14 (`LeaderboardController och FullListController skopar frågan till den valda källan`), which K15 omits. AD-10 governs auth/exposure, not source-merging, so its citation there reads as a stretch. *Fix:* add AD-14 to K15's "Styrs av" list (AD-3 alone already covers the storage-level justification; AD-10 can be dropped).
