# Sprint Change Proposal — Stockpicker

## Section 1 — Issue Summary

**Problem.** The product brief (K1) and `SPEC.md` (Assumptions) both state the instrument
universe is fetched from *"Börsdatas API (gratisnivå)"* — a free tier. **There is no free
tier.** The Börsdata API wiki: *"Only Pro Members in Nordic Country can Apply for API
Key."* Without a paid Börsdata Pro subscription, `BorsdataAdapter` cannot run — in tests
or in production.

**Issue type:** misunderstanding of original requirements. The "gratisnivå" assumption was
never valid; it was copied unchallenged from the brief into the addendum
(*"Gratisnivå finns; nyckel krävs"*), `SPEC.md`, and `epics.md`.

**Discovery.** During `bmad-build` for Story 2.2 (`UniverseSync`), which needed a live
`bin/show-universe.php` run against the real Börsdata API to pin the adapter constants.
The operator has no Börsdata account and — this being a personal, low-cost learning
project — chose not to buy a Pro subscription. Universe source: **Avanza's public stock
listing** (the same inofficial-endpoint class already used for owner counts, no key).

**Evidence.**
- Börsdata API wiki, "Getting Started": Pro-membership-only API keys.
- `config.php` has no `borsdata` section; `Config::borsdataApiKey()` throws.
- `addendum.md` §"Källa: Börsdata" and `brief.md` §"Öppna frågor" both already flagged
  free-tier *coverage* as unverified — but not the existence of the free tier itself.

## Section 2 — Impact Analysis

churn logging + resilience. Only the *source* changes. Stories 2.3–2.6 (hardening) are
untouched. No epic added, removed, or resequenced. **MVP scope unchanged and still fully
achievable.**

## Section 3 — Recommended Approach

**Hybrid: Direct Adjustment (planning docs) + Partial Rollback (Story 2.1 code) +
re-spec (Stories 2.1 & 2.2).**

- **Why not pure Direct Adjustment:** Story 2.1's merged implementation is Börsdata-shaped
  end to end; it cannot be salvaged by editing stories. The adapter must be rebuilt.
- **Why not full rollback:** only Story 2.1's adapter code is Börsdata-specific.
  `UniverseEntry`, and every Epic 1 story, stand. A full Epic 2 rollback would be wasteful.
- **Why not MVP review:** the universe capability (CAP-1) is unchanged and still
  achievable via a free source already inside the architecture's scope.

**Effort:** Medium. Doc edits are small and done. The Story 2.1 v2 adapter is a fresh
implementation of a similar-sized class. Story 2.2's `UniverseSync` logic is ~90%
reusable once regenerated against the new adapter.

**Risk:** Low–Medium. The one open risk is Avanza's listing endpoint — path, filter
syntax, and whether it cleanly yields all four list segments with ISIN + `orderbookId`.
Mitigated by making live verification an explicit AC of Story 2.1 v2 (capture a real
response, document the schema in `addendum.md`, build fixtures from it) before Story 2.2
consumes the list. No new ToS surface beyond the already-accepted Avanza endpoints; no
recurring cost.

**Scope classification:** Major but contained — architecture spine + canonical contract
(`SPEC.md`) edited and one merged story rebuilt, but the epic list, story sequencing, and
MVP are all intact.
