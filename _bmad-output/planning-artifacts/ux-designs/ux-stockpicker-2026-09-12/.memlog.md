- (decision) Fresh design — not reusing existing planning docs (brief/epics/architecture) as sources; user opted to start clean.
- (decision) Purpose: a website UI to view/explore stockpicker's owner-count data (currently only accessible via SSH scripts and raw cron JSON).
- (decision) Auth: simple login, username + password.
- (decision) Form factor: single responsive website, must work well on both mobile and laptop — not separate native apps.
- (decision) Key view: leaderboard/ranking of stocks by number of owners ("what stocks has the most owners").
- (decision) Key view: new-owner delta vs. previous day, shown both as absolute count and as percent.
- (assumption) Future (explicitly out of this round's scope per user): comparing owner counts over user-selectable time ranges — days/weeks/months/years.
- (decision) Single-user login only: one hardcoded username/password, no registration or multi-account support needed.
- (decision) Avanza vs Nordnet shown via a source switcher/tab, not merged or side-by-side.
- (decision) Core journey: Top 10 most-popular-stocks-today leaderboard (by owner count, per source), each row showing day-over-day change (both count and percent).
- (decision) Core need (stated explicitly): a day-over-day uptick is not enough signal on its own — user wants to distinguish steady, sustained owner-count growth from short-term hype/spikes by checking historical trend before trusting a leaderboard mover. Backend already computes exactly this: up_streak (consecutive up-days), spike_score (anomaly vs trend), sma_7/30/90 (smoothed trend) via the owner_count_metrics view.
- (assumption) Visual direction: light theme leaning, not firmly committed yet — user open to exploring further.
- (decision) Leaderboard glance signal: a compact 'plus days / minus days' streak indicator per row (e.g. '+7 / -2'), not just a single up-streak number — lets user judge momentum without tapping in.
- (note) Backend gap to flag for build later: owner_count_metrics.up_streak only tracks the CURRENT consecutive up-day count (resets to 0 on any down/flat day) — it has no symmetric down-day streak or a rolling plus/minus day tally. UX requires both directions; this is a data requirement to hand to architecture/build, not something to solve here.
- (decision) Historical trend view must support the full flexible range picker (day/week/month/year) from this design, even though real data is currently thin — needs a graceful 'not enough history yet' state, consistent with the backend's own null-until-N-rows convention (sma_7/30/90).
- (decision) Leaderboard IA: Top 10 is the landing view; a clear action reveals the fuller ranked list beyond the top 10 (search/scroll/page through all ~740 tracked instruments).
- (decision) Confirmed scope: ship the existing current up-streak value now (available today). Symmetric plus-days/minus-days tally is explicitly deferred to a later backend enhancement, not blocking this design round.
- (decision) Add: a second leaderboard ranking sorted by sustained trend quality ('steady growers' — high up-streak, sma_30 uptrend, low spike_score), distinct from the 'most owners today' level-based ranking.
- (decision) Add: a spike flag badge (based on spike_score) shown directly on leaderboard rows currently exhibiting an anomalous jump.
- (decision) Add: stock detail page shows both sources' trend lines together (still visually distinct, never merged) for cross-source hype validation, in addition to the tab switcher used elsewhere.
- (decision) Add: a watchlist/favorites feature to pin stocks of interest for a quick-check view.
- (assumption) Deferred (explicitly, not this round): proactive email/notification alerts when a stock crosses into a steady-growth pattern. Revisit later; backend already has an email-alarm plumbing pattern (alarm.email) that could be reused.
